# D97CT persistent IORegistry-state diagnostic design

Purpose: replace the inconclusive early unified-log observation channel without changing the functional experiment.

Safety invariants:
- observe-only;
- no page mutation;
- no Root Patch;
- no accelerated boot;
- exact Tahoe 25G82 gate;
- Haswell gate;
- explicit -ocmcdiag gate;
- exact x86_64h dyld shared-cache vnode/path gate;
- exact D97CN site/cave page offsets;
- exact site preimage and cave-zero checks;
- original Apple _cs_validate_page always called first.

Observation architecture:
1. _cs_validate_page callback updates only bounded atomic counters/status fields after the existing read-only checks.
2. No IORegistry property allocation/write is done inside the code-sign validation callback.
3. A preallocated thread_call publisher runs asynchronously once per second during the bounded early-boot window and mirrors atomic state into the existing OCLPMetalCompat IOService properties.
4. Properties include activation/build/CPU gates, route result, site count/preimage/validated/tainted/nx and cave count/window18/full208/validated/tainted/nx.
5. Publisher stops after both site and cave have been observed or after a bounded timeout.

This separates target timing from IOLog/unified-log buffering and preserves D97CO semantics.
