## Apple dyld primary-source correction
Apple dyld populates each `imagesText` UUID from the cache builder's selected input Mach-O header. It raw-copies that input slice's segments/header and adjusts segment/load-command metadata without replacing `LC_UUID`. Therefore the D226 value observed in both `imagesText` and the cached Mach-O header is the selected cache input slice UUID, not a new UUID generated by cache optimization.

Authoritative terminology:

- incorrect retired label: `CACHE_OPTIMIZED_UUID`;
- correct label: `CACHE_INPUT_SLICE_UUID`;
- current cache input identity: `D2265480-60EB-3526-BAF7-2D6596149186`;
- visible/PSP donor identity: `D5CE0008-587C-3861-971A-4BAEFB7B9C5B`;
- same-input UUID identity: `NO`.

Apple preserves an intra-segment VM delta only for the same exact selected input image. A standalone D5CE file offset may be numerically usable as a VM-relative `__TEXT` offset only after same-slice/build identity and segment topology are proved. D97AEW does not satisfy that identity condition.
